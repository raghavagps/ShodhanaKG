## 1. Architecture Overview & Access Patterns

The ShodhanaKG backend exposes **70 functional endpoints** under the `api/` directory:

- **17 Core Web & Application Services**: Power the frontend UI explorers (Disease, Compound, Integrated), global knowledge graph analytics, search, reference catalogs, dynamic multi-hop semantic queries, and the conversational AI chatbot gateway.
- **53 Allowlisted Graph Traversal Endpoints**: Registered in [`ChatbotOrchestrator::$allowlist`](../api/core/ChatbotOrchestrator.php). These execute deterministic, schema-constrained ArcadeDB traversals with strict **Evidence Correlation** to eliminate cross-join hallucinations:
  - **40 Direct HTTP Endpoints**: Expose a standalone HTTP execution block (`if (basename(__FILE__) === ...)`) accepting query parameters via `GET`, while simultaneously exporting callable `execute_*()` routines.
  - **13 Orchestrator-Managed Traversal Functions**: Export modular `execute_*()` routines designed for in-process execution by `ChatbotOrchestrator` without spawning secondary HTTP subprocesses.

### Response Conventions & Error Handling
- **Standard Success**: Returns HTTP 200 with `{ ok: true, ... }` via [`api_ok()`](../api/response.php) or canonical traversal schema `{ status: 'success', entity: {...}, path: [...], results: [...] }` via [`KnowledgeNormalizer::formatCanonical()`](../api/core/KnowledgeNormalizer.php).
- **Standard Error**: Returns appropriate HTTP status codes (400, 404, 405, 500, 503) with `{ ok: false, error: { code, message, details } }` via [`api_fail()`](../api/response.php).
- **Streaming Transport**: [`/api/chatbot_response.php`](../api/chatbot_response.php) supports Server-Sent Events (`text/event-stream`) when `stream: true`, streaming incremental tokens and emitting `context` and terminal `done` events with authoritative metadata.
- **In-Process Caching**: Static caching in `GraphRead.php` and `SemanticQuery.php` accelerates repeated schema queries and node property lookups within request lifetimes.
