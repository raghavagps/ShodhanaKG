# Interface, reference search and chatbot updates — 7 October 2026

Implemented locally. No production deployment, KG write, reference-catalogue rewrite or frozen evaluation-fixture modification was performed. This is implementation validation, not a final release benchmark or scientific/clinical validation.

## Delivered behavior

1. Removed the Hindi/English switch, language provider/context, dictionaries, local translation service and translation hooks. UI strings are English; stored KG text remains unchanged. The old localStorage preference is inert. Dynamic navigation keys use an English-only label map.
2. Removed reference lookup/classification diagnostic wording from shared citation displays. Unknown references remain neutral text without guessed links. A presentation copy removes diagnostic reference fields from chatbot technical views; the original response and classifier metadata remain intact. Meaningful stored edge properties are preserved.
3. Added `/advanced-search` and a navbar link visible on desktop/mobile. The read-only `reference-search.php` endpoint searches KG-bound PMID/AYUSH references, exact identifiers, stored text, domain, entity type and relationship. Results retain separate namespaces and exact supporting edge IDs; Open in Explorer preserves node ID/type and chooses its appropriate domain. No external publication discovery is performed. Result pages contain 25 reference groups by default (maximum 100).
4. Added 13 curated introductory/help FAQs, grouped as About Shodhana and Using ShodhanaKG. Only four appear initially. A versioned backend catalogue holds answers, bounded phrase aliases, source references and review status; the frontend contains questions only. Optional `faq_id` is allowlisted. FAQ responses have separate background/help labels and no fabricated KG citations. JSON/SSE carry identical terminal FAQ metadata; frontend SSE context handling now preserves background source links. Existing resolved KG context is not replaced by FAQ content.
5. Broad entity-information requests return all nonempty stored public fields. Explicit descriptions and named-property requests remain specific, and missing fields are not inferred. Zero/false values are retained. Original node RID/type/keys remain in node evidence.
6. All three Graph Views use a configurable initial budget (default 300, presets 120/300/500). The server orders eligible nodes fairly by category while preferring connected candidates and retaining seeds. Visibility filters apply before allocation. Load more, Load all matching, Pause and Cancel use bounded continuation pages (at most 300 nodes and 1,000 edges). Edge-only continuation pages avoid losing edges after node loading. Cursors reject changed results. Cytoscape updates retain existing positions and selection. Compound connected-only filtering and Integrated Bridge filtering remain intact. Completed path metadata follows its supporting edges. Exports cover displayed elements.

“All matching” preserves the current query/traversal scope; it does not mean all database records. Seed/connector constraints can prevent equal category counts. The existing Integrated Explorer category allowlist is preserved rather than expanded by this change.

## API and operational notes

- Existing graph clients keep their original interface. The new opt-in `progressive=1` contract adds `budget`, `cursor`, visibility filters, loaded/matching counts and per-type counts. Pages are bounded; the server still reconstructs the current matching traversal to validate continuation. A 100,000-record read guard returns an explicit error rather than claiming a truncated graph is complete. This is not evidence of arbitrary-scale deployment capacity.
- The optional `KG_READ_CACHE_DIR` for reference-search snapshots must be writable and outside the document root. Cache lifetime is 60 seconds; schema/catalogue changes change the cache key. If unavailable, requests read current KG records without writing a cache. In this validation run no cache directory was configured. Set a D:-located directory for local use; deployment configuration was not changed.
- Advanced Search searches stored text, not article full text. It offers single entity-type and relationship selections; multiple simultaneous selections within those fields are not implemented.
- FAQ sources include AIIA's Seasonal Panchakarma material and CCRAS Drug Development Guidelines. The checked date is recorded in the catalogue. **Domain-expert review remains pending**; source-backed introductory wording is not clinical validation. Production was not updated.
- New code remains PHP 5.6 compatible. No runtime dependencies were added.
